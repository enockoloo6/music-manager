# 🎹 Universal Keyboard Song & Style Manager

A digital songbook designed for keyboardists to store and retrieve specific keyboard settings (Styles, Tempo, Key and Menu Location) across multiple hardware models like the **Yamaha PSR-S670**, **PSR-S650**, **PSR-SX700**, **Genos** and more.

## 🚀 The Problem it Solves
Keyboardists often forget which specific rhythm or "Style" they used for a song, especially when moving between different keyboard models. This app acts as a **"second brain"** — mapping your entire repertoire to specific keyboard settings so you can perform without searching through menus. A single song can store multiple beats across different keyboards and categories (Ballad, Country, Rumba, etc.), all visible at a glance.

```js
createClient(url, key, {
```

Music Manager only uses its own:


Other applications should NOT insert into this table.

## 🗄️ Database Schema

All app tables exist inside:

```sql
music_manager
```

### Required tables

```sql
create schema if not exists music_manager;

create table music_manager.keyboards (
  id bigint generated by default as identity primary key,
  model_name text not null unique
);

create table music_manager.songs (
  id bigint generated by default as identity primary key,
  song_name text not null unique
);

create table music_manager.styles (
  id bigint generated by default as identity primary key,
  song_id bigint references music_manager.songs(id) on delete cascade,
  keyboard_id bigint references music_manager.keyboards(id),
  beat_name text not null,
  tempo int,
  musical_key text,
  keyboard_location text,
  style_category text,
  notes text,
  created_at timestamptz default now()
);

create table music_manager.profiles (
  id uuid primary key references auth.users(id),
  email text,
  is_approved boolean default false,
  is_admin boolean default false,
  is_super_admin boolean default false,
  default_keyboard_id bigint references music_manager.keyboards(id)
);
```

## 🔐 Required RPC Functions

### get_all_profiles

```sql
create or replace function music_manager.get_all_profiles()
returns setof music_manager.profiles
language sql
security definer
set search_path = music_manager, auth, public
as $$
  select *
  from music_manager.profiles
  order by email;
$$;
```

### admin_update_profile

```sql
create or replace function music_manager.admin_update_profile(
  target_id uuid,
  new_is_approved boolean,
  new_is_admin boolean
)
returns void
language plpgsql
security definer
set search_path = music_manager, auth, public
as $$
begin
  if not exists (
    select 1
    from music_manager.profiles
    where id = auth.uid()
      and is_admin = true
  ) then
    raise exception 'Only admins can update profiles';
  end if;

  if exists (
    select 1
    from music_manager.profiles
    where id = target_id
      and email = 'enockoloo6@gmail.com'
  ) then
    raise exception 'Protected super admin cannot be modified';
  end if;

  update music_manager.profiles
  set
    is_approved = new_is_approved,
    is_admin = new_is_admin
  where id = target_id;
end;
$$;
```

Reload schema cache after creating functions:

```sql
notify pgrst, 'reload schema';
```

## 🔓 Expose Schema in Supabase

Go to:

```text
Supabase → Project Settings → Data API
```

Add:

```text
music_manager
```

under:

```text
Exposed Schemas
```

Without this, the app will fail with:

```text
Invalid schema: music_manager
```

## 🛠️ Troubleshooting

| Problem | Fix |
|---|---|
| `Invalid schema: music_manager` | Add `music_manager` to Supabase Exposed Schemas |
| Songs load empty | Run `notify pgrst, 'reload schema';` |
| Admin panel empty | Create `get_all_profiles()` RPC |
| Approve/Admin buttons fail | Create `admin_update_profile()` RPC |
| White screen on Netlify | Ensure environment variables exist |
| 404 on refresh | Add `public/_redirects` |
